# 山泉弹珠台 · 架构文档

## 技术选择

采用 TypeScript + Vite 的静态前端，Canvas 2D 绘制具有立体感的游戏场景，HTML / CSS 负责可访问的按钮、实时数据和结果面板。纯客户端部署到 Vercel CDN，无服务端、数据库和运行时密钥；资源均随构建部署。

不引入 WebGL 引擎：本项目是固定镜头的单球弹珠台，Canvas 的分层绘制足以表现山城微缩景观，移动端启动和渲染成本更低。物理模拟与绘制解耦，后续可更换渲染层。

2026-10-25 Windows 比例修正：桌面和手机均保持 540:820 原始比例，移除桌面 6:5 横向拉伸及局部比例补偿。`fitViewport` 为所有画面元素提供同一个缩放系数；即使容器比例意外变化，也以居中留白保护原始形状。ResizeObserver 只同步像素尺寸和统一变换。桌面将 HUD、救援和按钮移到球台左侧，利用完整视口高度放大；放大模式的品牌和设置移到目的地上方。

## 模块边界

```text
src/main.ts           HTML 界面、输入映射、UI 同步、生命周期
src/game/model.ts     状态机、积分、关卡、计时、路线与救援
src/game/physics.ts   固定步进、圆球与圆形/线段碰撞、挡板冲量
src/game/renderer.ts  分层山水、山城弹珠台、水滴、粒子与终点
src/game/viewport.ts  统一缩放、居中适配、DPR 像素尺寸
src/game/audio.ts     Web Audio 撞击音、水声与结算旋律
src/game/storage.ts   版本化本地纪录与静音偏好、异常回退
src/style.css         响应式布局、触摸控件、交互与无障碍
public/assets/        本地品牌与场景素材
tests/                物理和状态机回归、浏览器操作脚本
docs/                 需求、设计、验收证据与部署说明
```

## 状态与数据流

`ready → playing ⇄ paused → won | lost → playing`

有效游玩时依次推进 `source → bottling → delivery`。状态机是分数、阶段、计时、救援次数和结果的唯一来源。输入层只维护挡板按下状态与一次性操作，固定步进循环更新模型，渲染层只读模型，DOM 在状态变化时同步。

物理场地采用固定逻辑尺寸 540 × 820，显示时等比缩放；Canvas 适配设备像素比并将 DPR 限制为 2。使用 1/120 秒固定物理步长，限制单帧补偿量，防止卡帧导致球穿墙。速度上限和碰撞位置修正保证模拟稳定。挡板按键会触发有方向的冲量；重力、圆形保险杠和斜轨共同形成可重复操作的弹珠体验。

岩层有效撞击累计到 180 米，灌装机关在出泉后开放，配送入口在灌装后开放。三条岔路具有不同的物理终点，开放轨道对附近球体施加微弱横向水流，球体仍须实际进入入口；不通过定时器直接判赢。路线选择决定最终杯子与场景，旋律来自本局实际碰撞。救援会把球送回发射道并保留关卡进度；需要主动发射继续。

## 声音与动效

首个用户手势创建或恢复 AudioContext。碰撞音使用五声音阶的合成音与滤波噪声，结算将本局音符编成水声短曲。静音关闭总增益；后台暂停时停止持续音频。减少动态模式去掉背景漂浮、拖尾和额外粒子，保留必要物理运动。

## 数据与可靠性

使用带版本键的 localStorage 保存最高分、最佳用时、已送达场景与静音偏好；读取失败、隐私模式、无效 JSON 均回退为默认值，不能阻止游戏启动。无个人身份数据、网络请求和第三方追踪。

每局开始时复制纪录基线。结算后切换杯子，直接更新本局结果，并根据同一基线重新结算这一杯，避免重复增加送达次数、错误集齐三个杯子或覆盖更早的真实纪录。分数与耗时不变，静音偏好取当前值。

## 验证与部署

- `npm run check`：TypeScript 类型检查。
- `npm test`：状态机、72 秒计时、暂停、路线、救援、碰撞的确定性测试。
- `npm run build`：生成 `dist/`，Vercel 使用相同构建命令与输出目录。
- 本地浏览器检查首次打开、键盘与触摸输入、完整获胜与失败、后台暂停、重玩、纪录恢复、375px / 768px / 1440px 布局与控制台错误。
- 每个独立验收点通过后 commit / push；只有通过检查的源码进入正式部署。
- Vercel 正式 URL 需实际检查 HTTP 成功响应和浏览器可玩性。部署信息、提交与检查结果记入 `docs/ACCEPTANCE.md`。
